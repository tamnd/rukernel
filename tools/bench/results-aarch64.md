# rukernel-bench: the first table

This file is generated by `tools/bench/run.py` from the serial logs of the run. A copy of the logs is in `tools/bench/logs-aarch64`. Do not edit this file. Run the script again to make a new table.

- Date: 2026-10-29
- rukernel commit: 44169fc with the #442 changes (release build of the `rukernel` package)
- Linux: `Image` (Linux 7.3 with the arm64 defconfig, from tools/bench/linux-arm64.sh)
- Host: AMD EPYC Processor (with IBPB), 6 CPUs, Linux 6.8.0-147-generic
- QEMU: QEMU emulator version 8.2.2 (Debian 1:8.2.2+ds-0ubuntu1.18), `-machine virt,gic-version=3 -m 1G -smp 1 -accel tcg -cpu cortex-a72`, the same for both kernels
- Userland: one static musl program (`tools/bench/bench.c`) as /init in the same initramfs for both kernels
- Linux command line: `console=ttyAMA0 rdinit=/init mitigations=off quiet panic=-1 -- 10 100`
- rukernel command line: `console=ttyAMA0 rk.test=init rdinit=/init -- 10 100`
- Runs: 10 runs for each benchmark after one warm-up run, scale 100

These are QEMU numbers, not native numbers. Without KVM, QEMU emulates each instruction (TCG). The cost of an emulated instruction is not the cost on hardware. Privileged instructions, page table changes, TLB flushes and device access cost much more than on hardware, so the ratio can be different on hardware. Use the table to find the large differences, not to compare small ones. The run does not obey all the rules of spec/19-rukernel-bench.md: it is one machine, in a VM, with no Mann-Whitney test, with one Linux build (Linux 7.3 with the arm64 defconfig, from tools/bench/linux-arm64.sh), and with no check of the mitigations. Linux runs with `mitigations=off` because rukernel has no mitigations yet. Under TCG, Linux is very slow on the rows that change page tables or switch tasks (`ctxsw`, `thread`, `fault`, `mmap`, `fork`). The cause is not known yet. Thus a green row in this group does not show that rukernel is faster on hardware.

Each value is the median of the runs. The value in parentheses is the interquartile range as a percentage of the median. The ratio is the time on rukernel divided by the time on Linux. For the throughput rows (MB/s), it is the throughput on Linux divided by the throughput on rukernel. Thus 1.00 is equal and a higher ratio is slower. A ratio above 2.00 is a red row, marked **red**. A benchmark that did not run is red too.

To make this table again on a host with QEMU and a C compiler for static musl programs:

```
cargo build --release --package rukernel --target aarch64-unknown-none
tools/bench/run.py --arch aarch64 --rukernel target/aarch64-unknown-none/release/rukernel \
    --linux /root/rk-linux-arm64/build/arch/arm64/boot/Image --cc /root/rkcc/musl-cc-aarch64 --runs 10 --table tools/bench/results-aarch64.md
```
