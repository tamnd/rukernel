# Notes for the LTP result tables. Each line has a test name, a tab and a note.
# report.py puts the note in the table, and the note gives the cause of the test in the work that
# remains. Without a note, the table shows the reason from the log. A test name can have the
# runtest file before it, as net.ipv6:ping601, when two runtest files have the same name.

ksm02	The test needs a NUMA system with a node that has memory and CPUs. rukernel has no NUMA (TCONF).

ksm06_1	The test needs CONFIG_NUMA and two NUMA nodes with memory, for merge_across_nodes. rukernel has no NUMA (TCONF).
ksm06_2	The test needs CONFIG_NUMA and two NUMA nodes with memory, for merge_across_nodes. rukernel has no NUMA (TCONF).
asapi_01	The test wants getprotobyname("hopopt") to give 0. The LTP build links musl, and the protocol table of musl is built in and has "ip" for 0, so this check fails on Linux with musl too. The other checks of asapi_01 pass.
fork13	The test runs for 600 s (.runtime = 600), and it forks until the time ends. The runner limit is 240 s, so the runner stops it. It is not a hang: the after kernel did 146018 forks in the time.
fork14	The test maps 1 GiB 16384 times. With 1 GiB of memory or less, the overcommit check refuses each map, as on Linux, and the test gives TCONF. Before, the maps were allowed and the test did not stop in the time limit.
hackbench01	The test sends 20 M socket messages (50 groups x 20 senders x 20 receivers x 1000 messages). Under QEMU without KVM this takes more than the time limit. A smaller run (hackbench 5 process 100) passes.
hackbench02	The test sends about 8 M socket messages. Under QEMU without KVM this takes more than the time limit. A smaller run passes.
shm_test01	The test calls sched_yield for each byte of a map of up to 4 MB, about 40 M system calls. Under QEMU without KVM this takes more than the time limit. shm_test -l 1 -t 2 also takes more than 240 s.
starvation	The test calibrates its runtime from the speed of the machine. Under QEMU without KVM it asks for about 6 to 9 min, more than the 240 s limit of the runner. Before #408 the woken thread did not get the CPU in time, and the test did not stop in its own time limit (TBROK). With the EEVDF wakeup preemption of #408, the test passes in about 7 min with --timeout 900.
preadv203	Since #408, RWF_NOWAIT on tmpfs gives EOPNOTSUPP, as on Linux, and the test gives TCONF on tmpfs before its writes. On ext2 the test passes when a read with RWF_NOWAIT finds a page that is not in the cache and gets EAGAIN. In some runs no read gets EAGAIN, and the test fails.
preadv203_64	The same as preadv203: TCONF on tmpfs, and ext2 passes when a read gets EAGAIN.
mmapstress02	The musl libc gives ENOMEM for each brk and sbrk call with a size that is not 0. An LTP tree from build.sh before #415 does not have the brk and sbrk of build.sh, so the test cannot run. With them the test passes.
mmapstress03	The musl libc gives ENOMEM for each brk and sbrk call with a size that is not 0. An LTP tree from build.sh before #415 does not have the brk and sbrk of build.sh, so the test cannot run. With them the test passes.
mmapstress05	The musl libc gives ENOMEM for each brk and sbrk call with a size that is not 0. An LTP tree from build.sh before #415 does not have the brk and sbrk of build.sh, so the test cannot run. With them the test passes.
mmapstress08	The musl libc gives ENOMEM for each brk and sbrk call with a size that is not 0. An LTP tree from build.sh before #415 does not have the brk and sbrk of build.sh, so the test cannot run. With them the test passes.
sbrk01	The musl libc gives ENOMEM for each brk and sbrk call with a size that is not 0. An LTP tree from build.sh before #415 does not have the brk and sbrk of build.sh, so the test cannot run. With them the test passes.
overcommit_memory02	With -R 0 the commit limit is 0 (no swap), and the test then reads the sysctl back with fopen. musl malloc needs a new mmap for the FILE, which the strict policy refuses, so the test gives TBROK instead of the TCONF that it gives with glibc.
vma02	Needs NUMA and mbind (#322) (TCONF).
vma03	Needs mmap2, which only a 32 bit kernel has (TCONF on x86_64).
vma04	Needs NUMA and mbind (#322) (TCONF).
vma05	Needs gdb in the guest, which the LTP image does not have (TCONF).
cgroup	cgroup_regression_test mounts the cgroup v1 file system, and rukernel has only cgroup v2, so mount gives ENODEV (TFAIL). Two cases need CONFIG_SCHED_DEBUG and CONFIG_LOCKDEP (TCONF).
memcg_failcnt	The memcg_* scripts test the memory controller of cgroup v1. rukernel mounts the memory controller on cgroup v2 (TCONF).
memcg_stat	The memcg_* scripts test the memory controller of cgroup v1. rukernel mounts the memory controller on cgroup v2 (TCONF).
cgroup_fj_function_freezer	The test needs the freezer controller of cgroup v1. The cgroup v2 freezer is cgroup.freeze, not a controller (TCONF).
controllers	test_controllers.sh needs /bin/bash, and the image has no bash, so the shell gives "not found" (exit 127). On cgroup v2 the script also stops with TCONF.
memcg_stress	The test runs for 900 s by design, more than the 240 s limit of the runner, so the runner stops it.
cgroup_fj_function_cpuset	The test passes alone. In the controllers batch it runs after memcontrol03 and memcontrol04, which stop on a timeout and leave their cgroups under /sys/fs/cgroup/ltp. The ltp cgroup then keeps cpuset in cgroup.subtree_control, so the write of -cpuset to the root cgroup.subtree_control gives EBUSY (TWARN), as on Linux. Linux 6.8 in the same runner gives the same TWARN after memcontrol03. run.py now runs memcontrol03 and memcontrol04 each in their own boot (ALONE), so the cgroups that they leave do not stay for the next tests.
cgroup_fj_stress_memory_10_3_each	The test makes about 1100 cgroups, moves about 1000 tasks between them, and then stops the tasks. Under QEMU without KVM it ends in about 230 s on a quiet host, near the 240 s limit of the runner. When the host is busy, the test does not end in the limit. run.py gives it a limit of 600 s in LIMITS.
memcg_test_3	The test makes and removes a cgroup in a loop until a child sends it 50000 SIGUSR1 signals. With one CPU under QEMU without KVM, the parent gets about 40 signals per second, and the test needs about 420 per second to end in its limit of 120 s (TBROK, exit 2). Linux 6.8 in the same runner gets 23 to 63 signals per second and fails in the same way.
memcontrol03	Each child writes 50 MB of page cache to ext2 and fsync, and the parent waits 10 s for each child. Under QEMU without KVM the write takes about 11 s, so the wait ends with ETIMEDOUT (TBROK). The cleanup of the library then gives EBUSY for the cgroups that stay, again and again until the time limit. Linux 6.8 in the same runner also stops with TBROK, one step later, and leaves its cgroups too.
memcontrol04	The test fails as memcontrol03: the first child does not write 50 MB of page cache in the 10 s wait of the parent under QEMU without KVM (TBROK). Linux 6.8 in the same runner passes 4 checks and then stops with TBROK. After memcontrol03 in one boot, the test device is still mounted and mkfs fails. After the TBROK, the test process can end before it removes its cgroups, for example when a child still runs. The cleanup of the library then removes test-PID, which still has these cgroups, so rmdir gives EBUSY, as on Linux. The tst_brk of the cleanup calls the cleanup again, and this recursion ends in a segfault when the stack is full. A cgroup without tasks and without child cgroups is removed, also when it has charges of page cache.
