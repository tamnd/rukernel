# Notes for the LTP result tables. Each line has a test name, a tab and a note.
# report.py puts the note in the table, and the note gives the cause of the test in the work that
# remains. Without a note, the table shows the reason from the log. A test name can have the
# runtest file before it, as net.ipv6:ping601, when two runtest files have the same name.
cachestat03	Needs hugetlbfs, which rukernel does not have (TCONF).
fanotify05	The test makes 3 x 16385 files on ext2. Under QEMU without KVM on a busy host, this can take more than the time limit of the test (172 s, TBROK). It passes when the host is less busy.
ksm02	The test needs a NUMA system with a node that has memory and CPUs. rukernel has no NUMA (TCONF).
ksm02_1	The test needs a NUMA system with a node that has memory and CPUs. rukernel has no NUMA (TCONF).
ksm04	The test needs a NUMA system with a node that has memory and CPUs. rukernel has no NUMA (TCONF).
ksm04_1	The test needs a NUMA system with a node that has memory and CPUs. rukernel has no NUMA (TCONF).
ksm06	The test needs CONFIG_NUMA and two NUMA nodes with memory, for merge_across_nodes. rukernel has no NUMA (TCONF).
ksm06_1	The test needs CONFIG_NUMA and two NUMA nodes with memory, for merge_across_nodes. rukernel has no NUMA (TCONF).
ksm06_2	The test needs CONFIG_NUMA and two NUMA nodes with memory, for merge_across_nodes. rukernel has no NUMA (TCONF).
asapi_01	The test wants getprotobyname("hopopt") to give 0. The LTP build links musl, and the protocol table of musl is built in and has "ip" for 0, so this check fails on Linux with musl too. The other checks of asapi_01 pass.
fork13	The test runs for 600 s (.runtime = 600), and it forks until the time ends. The runner limit is 240 s, so the runner stops it. It is not a hang: the after kernel did 146018 forks in the time.
hackbench01	The test sends 20 M socket messages (50 groups x 20 senders x 20 receivers x 1000 messages). Under QEMU without KVM this takes more than the time limit. A smaller run (hackbench 5 process 100) passes.
hackbench02	The test sends about 8 M socket messages. Under QEMU without KVM this takes more than the time limit. A smaller run passes.
shm_test01	The test calls sched_yield for each byte of a map of up to 4 MB, about 40 M system calls. Under QEMU without KVM this takes more than the time limit. shm_test -l 1 -t 2 also takes more than 240 s.
starvation	The test calibrates its runtime from the speed of the machine. Under QEMU without KVM it asks for about 9 min, more than the 240 s limit of the runner. starvation -l 20000 passes.
preadv203	On ext2 the test passes: RWF_NOWAIT gives EAGAIN when a page is not in the cache. On tmpfs the test fails, because tmpfs pages are always in memory and a read never gives EAGAIN.
preadv203_64	The same as preadv203: ext2 passes, tmpfs fails, because tmpfs pages are always in memory.
