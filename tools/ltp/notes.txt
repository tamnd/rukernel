# Notes for the LTP result tables. Each line has a test name, a tab and a note.
# report.py puts the note in the table, and the note gives the cause of the test in the work that
# remains. Without a note, the table shows the reason from the log. A test name can have the
# runtest file before it, as net.ipv6:ping601, when two runtest files have the same name.
fanotify05	The test makes 3 x 16385 files on ext2 while a fanotify group holds an event for each file. Before #475, each create in a directory examined each cached name in use, and the events keep their names in use, so the creates took a time that grew with the count of files (3.3, 8.7, 12.7 and 22.5 s for each 4096 files). The cache now removes unused names only when it doubles in size, the times stay at about 3 s for each 4096 files, and the test passed on server2 in a boot of 142 s (#475). Under QEMU without KVM on a very busy host, it can still take more than the time limit of the test (172 s, TBROK).

memcg_test_3	The test makes and removes a cgroup in a loop until a child sends it 50000 SIGUSR1 signals. With one CPU under QEMU without KVM, the parent gets about 40 signals per second, and the test needs about 420 per second to end in its limit of 120 s (TBROK, exit 2). Linux 6.8 in the same runner gets 23 to 63 signals per second and fails in the same way.
memcontrol03	Each child writes 50 MB of page cache to ext2 and fsync, and the parent waits 10 s for each child. Under QEMU without KVM the write takes about 11 s, so the wait ends with ETIMEDOUT (TBROK). The cleanup of the library then gives EBUSY for the cgroups that stay, again and again until the time limit. Linux 6.8 in the same runner also stops with TBROK, one step later, and leaves its cgroups too.
memcontrol04	The test fails as memcontrol03: the first child does not write 50 MB of page cache in the 10 s wait of the parent under QEMU without KVM (TBROK). Linux 6.8 in the same runner passes 4 checks and then stops with TBROK. After memcontrol03 in one boot, the test device is still mounted and mkfs fails. After the TBROK, the test process can end before it removes its cgroups, for example when a child still runs. The cleanup of the library then removes test-PID, which still has these cgroups, so rmdir gives EBUSY, as on Linux. The tst_brk of the cleanup calls the cleanup again, and this recursion ends in a segfault when the stack is full. A cgroup without tasks and without child cgroups is removed, also when it has charges of page cache.
