# LTP

This directory has the files that run the Linux Test Project (LTP) on rukernel, and the record of the results of the syscalls, mm, sched, net and pty groups. The exit of R4 uses the first four groups.

- `build.sh` builds LTP as static musl programs in an Alpine container. Without `--full`, it builds the tests of the `ltp` boot test. With `--full`, it builds all of LTP.
- `tests.txt` has the tests that `cargo xtask boot-test ltp` runs, and the reasons why other tests are not in it.
- `kconfig` tells LTP the kernel options of rukernel.
- `run.py` runs runtest files of LTP on rukernel under QEMU, in batches.
- `syscalls.md`, `mm.md`, `sched.md`, `net.md` and `pty.md` have the result of each test of a group.
- `notes.txt` has a note for some tests: the missing feature, or the pull request that fixed the test.
- `linux.txt` has the Linux code that each test checks, as paths in the Linux tree.
- `report.py` makes the result files from the logs of the runs, and `update.sh` copies the logs from the test server and runs `report.py`.

## How the tests run

`build.sh --full OUT` builds LTP at the tag in `build.sh` and installs it in `OUT/ltp`, as LTP installs itself in `/opt/ltp`. A test that does not build with musl does not stop the build. `OUT/notbuilt.txt` has the tests of the groups that have no program, and `OUT/src.tar.gz` has the sources of the tests for `report.py`. The build takes about 15 minutes on an x86-64 host with 6 cores.

`run.py` makes an ext4 image of the LTP tree, and splits the tests of each runtest file in batches of 60 tests. Each batch boots the kernel in QEMU, with BusyBox and an init script in the initramfs. The script mounts the image read only on `/ltp`, mounts tmpfs on `/tmp` and `/dev/shm`, brings up `lo`, and runs the tests one after the other, as `runltp` does. The second disk, `/dev/vda`, is the device of the tests that need one (`LTP_DEV`). `LTP_TIMEOUT_MUL` is 4, because QEMU without KVM is slow. The file `IMAGE.tree` next to the image has the path of the LTP tree that the image came from. When `--ltp` is another tree, `run.py` stops, and it does not make an image again that has no such file. Thus a run with another tree does not change an image that other runs use.

Each test runs in its own session with a time limit (200 seconds for the baseline). A test that runs longer by design has a larger limit in `LIMITS` of `run.py`, for example setsockopt11 with its runtime of 300 seconds. When the time is over, the script kills all the processes of the session, so one test that hangs does not stop the batch. When the kernel panics or hangs during a test, `run.py` records the result of the test and boots again with the next test. At most 2 batches run at the same time.

```sh
tools/ltp/build.sh --full ~/rkltp
cargo build --release --package rukernel --target x86_64-unknown-none
tools/ltp/run.py --kernel target/x86_64-unknown-none/release/rukernel --ltp ~/rkltp/ltp \
    --busybox target/x86_64-unknown-none/debug/busybox --out ~/rkltp/runs syscalls mm sched net pty
```

The boot tests download the static BusyBox to `target/x86_64-unknown-none/debug/busybox`. `net` runs each `runtest/net.*` file. `--only` runs only some tests, for example `--only fork01,mmap01`. A batch that is done does not run again, unless `--force` is given, so a second run continues a run that stopped. `--only @FILE` reads the tags from a file. `--first 101` numbers the batches from 101, so the run keeps the old logs, and `report.py` uses the newest result of each test. The baseline uses the release build of the kernel, because the debug build is 5 times slower under QEMU without KVM.

`--arch aarch64` runs the tests on the arm64 kernel, on the `virt` machine of `qemu-system-aarch64` with a GICv3 and TCG. `run.py` makes the arm64 `Image` from the ELF file of the kernel, and the console is `ttyAMA0`. `build.sh --arch aarch64` builds LTP for arm64 in an arm64 Alpine container. The host must run arm64 programs through qemu-user-static with binfmt, and the build is about 10 times slower than the x86-64 build. `LTP_TESTDIRS` sets the directories of the tests that the full build builds, so `LTP_TESTDIRS=testcases/kernel/syscalls` builds only the syscalls group. The arm64 BusyBox comes from `tools/busybox/build.sh` on the same host.

```sh
LTP_TESTDIRS=testcases/kernel/syscalls tools/ltp/build.sh --full --arch aarch64 ~/rkltp-arm64
tools/busybox/build.sh ~/rkltp-arm64/busybox
cargo build --release --package rukernel --target aarch64-unknown-none
tools/ltp/run.py --arch aarch64 --kernel target/aarch64-unknown-none/release/rukernel \
    --ltp ~/rkltp-arm64/ltp --busybox ~/rkltp-arm64/busybox/busybox --out ~/rkltp-arm64/runs syscalls
```

The tests of the network namespaces need the `ip` program of iproute2, because the `ip` applet of BusyBox does not have `ip netns` and the other commands that they use. `tools/ltp/build-ip.sh OUT_DIR` builds a static `ip` of iproute2 6.19.0 with musl in docker, and puts it in `OUT_DIR/ip`. Give it to `run.py` with `--ip OUT_DIR/ip`. The image then has it in /bin, before the applet of BusyBox.

The results are:

- pass: the test exits with 0.
- fail: the test exits with a different code. LTP gives an OR of 1 (`TFAIL`), 2 (`TBROK`) and 4 (`TWARN`), and a code with 32 is a `TCONF` with one of these.
- does not apply: the test exits with 32 (`TCONF`), because the kernel or the system does not have a feature that the test needs.
- timeout: the test did not stop in its time limit.
- panic, hang: the kernel panicked, or stopped to give output, during the test.
- not built: the program of the test did not build with musl.

## How to make the tables again

`update.sh` copies the logs of the runs from the test server and runs `report.py`. The script writes the four result files and the status and work sections of this file, so do not change these by hand:

```sh
tools/ltp/update.sh
```

The test server is `server3` by default. Set `RK_LTP_HOST` to use a different server, and `RK_LTP_DIR` to use a different directory on it. The directory has the output of `build.sh --full` and the batches of `run.py` in `runs`.

`report.py` can also run on logs that are on this computer:

```sh
tools/ltp/report.py --logs RUNS --src SRC/testcases --notbuilt NOTBUILT
```

Each test links to its source in LTP at the tag of `build.sh`, and the description is the first sentence of the description in the source. Each test also links to the code of the reference kernel, Linux 7.3, from `linux.txt`. The version comes from `tools/rk-abigen`. If the Linux tarball of `rk-abigen` is in its cache, `report.py` stops when a path of `linux.txt` is not in that version. When a test links to the wrong code, change `linux.txt`.

Write a new line in `notes.txt` when a pull request fixes a test, or when a test needs a feature that rukernel does not have. The note then shows in the tables and gives the group of the test in the work that remains. Without a note, `report.py` finds the cause in the first `TFAIL`, `TBROK` or `TCONF` line of the output of the test.
